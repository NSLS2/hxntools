# HXN PandA flyscan → ophyd-async in hxntools

## Context

Port the active HXN PandA flyscan workflow (`hxn-profile-collection/startup/93-scanplan-panda.py`: `fly1dpd`, `fly2dpd`, `flyscan_pd`, `HXNFlyerPanda`, `ExportSISDataPanda`; Xspress3 ROI export from `95-xspress3-panda.py`) into `hxntools` as an ophyd-async/Bluesky fly scan, preserving only the scientific intent: relative 1D/2D raster over PPMAC fine stages; PPMAC line gate (`M100`) → PandA dwell pulse train → Zebra TTL fan-out → Xspress3 + SIS3820 per-point acquisition; PandA encoder/timestamp capture supersampled `position_supersample`× per point; scan metadata; return to start. Behavior missing from upstream devices is added upstream (ophyd-async, nslsii PR #269), never by subclassing/overriding upstream classes in hxntools.

Scope (decided):
- XRF chain only: PandA `XF03IDC-ES-PANDA-1:`, Xspress3 via nslsii PR #269 on the community IOC `XF:03IDC-ES{Xsp:2}:`, SIS3820 `XF:03IDC-ES{Sclr:1}`, Zebra `XF:03IDC-ES{Zeb:1}:` TTL fan-out, optional fast shutter. Any ophyd-async `StandardDetector` supporting `EXTERNAL_LEVEL` can be passed as an extra detector (Merlin/Eiger not ported).
- Plans: `fly1dpd`, `fly2dpd` (no `fly2dcontpd`, `timescanpd`, `fly2dpd_repeat`, FIP/panda2).
- SIS3820 MCS detector + client-side HDF5 writer is new code developed in hxntools first (self-contained, for later move into nslsii `scaler-async`). nslsii PR #306 cannot be used: its `Scaler` is scalerRecord step counting only (MCS support was removed "until flyable file writing is figured out"), and it lives on a different nslsii branch than PR #269 while hxntools can depend on only one nslsii revision. The new MCS detector therefore covers only SIS38XX-template + mca records and does not duplicate any scaler-record signal from PR #306.
- Saved PandA settings stay at repo-root `config/standard-fly/`; plans take the directory path.
- `hxn-profile-collection` (separate repo) is not edited.

## Approach

### Composition rules (apply to every step)

- No hxntools class subclasses a concrete upstream device or logic (`HDFPanda`, `PulseBlock`, `Xspress3Detector`, `ADAcquireLogic`, …) and no hxntools class overrides an inherited method that already has behavior. HXN configuration is expressed by constructor arguments in factory functions, by `Settings` overlays, and by plan stubs.
- Subclassing remains only where ophyd-async's API requires a type, and these classes add no overrides of concrete behavior:
  - Logic interfaces `DetectorTriggerLogic`, `DetectorAcquireLogic`, `DetectorDataLogic`, `FlyableLogic`: ophyd-async discovers supported trigger modes by which `DetectorTriggerLogic.prepare_*` methods a subclass defines (`_get_supported_triggers` in `ophyd_async/core/_detector.py`), and `FlyableLogic` declares abstract hooks; implementing them requires subclassing.
  - Declarative containers (`EpicsDevice` IO class with annotated signals; a `StandardDetector` whose `__init__` only creates children and calls `add_detector_logics`): same shape as upstream `HDFPanda` and PR #269 `Xspress3Detector`. A bare `StandardDetector()` with attributes assigned afterwards would connect (`Device.__setattr__` registers children) but leaves children untyped for static checking and diverges from the nslsii layout the SIS module will move into.
- Flyers use `FlyableLogic.with_device(name=...)` (ophyd-async composition API), not `StandardFlyable` subclasses. Interfaces to non-ophyd collaborators are `typing.Protocol`s.

#### B2. SIS3820 MCS detector + HDF5 writer

New `src/hxntools/ophyd_async/__init__.py` (docstring only) and `src/hxntools/ophyd_async/sis3820.py`; imports only ophyd-async, bluesky, event-model, numpy, h5py, stdlib. Module docstring: SIS3820 multichannel-scaler acquisition via the EPICS mca module's SIS38XX driver, with client-side HDF5 writing of the per-channel arrays.

Enums: `Sis3820ChannelAdvance(StrictEnum)`: `INTERNAL = "Internal"`, `EXTERNAL = "External"`. `Sis3820InputMode(SubsetEnum)`: `MODE_0..MODE_3 = "Mode 0".."Mode 3"`. Use `ophyd_async.core.YesNo` for `CountOnStart`.

`class Sis3820McsIO(EpicsDevice)` (prefix = SIS38XX `$(P)`, e.g. `XF:03IDC-ES{Sclr:1}`; record names from `src/hxntools/struck_scaler.py` and the mca SIS38XX template):
- annotated: `acquiring: A[SignalR[bool], PvSuffix("Acquiring")]`; `nuse_all: A[SignalRW[int], PvSuffix("NuseAll")]`; `channel_advance: A[SignalRW[Sis3820ChannelAdvance], PvSuffix("ChannelAdvance")]`; `input_mode: A[SignalRW[Sis3820InputMode], PvSuffix("InputMode")]`; `count_on_start: A[SignalRW[YesNo], PvSuffix("CountOnStart")]`; `prescale: A[SignalRW[int], PvSuffix("Prescale")]`; `preset_real: A[SignalRW[float], PvSuffix("PresetReal")]`; `read_all: A[TriggerableCommand, PvSuffix("ReadAll")]`.
- `__init__(self, prefix: str, *, channel_numbers: Sequence[int], name: str = "")`: before `super().__init__(prefix, name=name)`: `self.erase_start = epics_signal_w(bool, f"{prefix}EraseStart", wait=False)`, `self.stop_all = epics_signal_w(bool, f"{prefix}StopAll", wait=False)` (comment: put-callback on these may not return until acquisition ends; completion is observed on `acquiring`), `self.mcas = DeviceVector({n: epics_signal_r(Array1D[np.int32], f"{prefix}Mca:{n}") for n in channel_numbers})`.
- Scaler-record `.CONT` is not touched: the SIS38XX `AcquireMode` record turns off scaler Autocount in MCS mode (mca SIS38XX documentation).

`@dataclass class Sis3820TriggerLogic(DetectorTriggerLogic)` (fields `mcs: Sis3820McsIO`, `input_mode: Sis3820InputMode`, `count_on_start: bool`):
- `config_sigs()` → `{mcs.channel_advance, mcs.input_mode, mcs.count_on_start, mcs.prescale, mcs.nuse_all}`.
- `prepare_level(num)`: `num == 0` → `ValueError("SIS3820 MCS acquisition must be finite (NuseAll > 0)")` (NuseAll is the only stop condition). Gather-set `channel_advance=EXTERNAL`, `input_mode=self.input_mode`, `count_on_start=YesNo.YES if self.count_on_start else YesNo.NO`, `prescale=1`, `preset_real=0.0`; then `nuse_all=num`. Only level triggering (bins delimited by the external gate) is implemented.

`@dataclass class Sis3820AcquireLogic(DetectorAcquireLogic)` (field `mcs`): `start_acquiring`: `await mcs.erase_start.set(True)`, then `await wait_for_value(mcs.acquiring, True, timeout=DEFAULT_TIMEOUT)` (no race: with external advance nothing ends acquisition before gate pulses arrive); `wait_for_idle`: `wait_for_value(mcs.acquiring, False, timeout=DEFAULT_TIMEOUT)`; `ensure_stopped`: `await mcs.stop_all.set(True)` then `wait_for_value(mcs.acquiring, False, timeout=DEFAULT_TIMEOUT)`. `ensure_ready` keeps the base default.

`class Sis3820HDFDataLogic(DetectorDataLogic)` — the SIS file writer:
- `__init__(self, path_provider: PathProvider, mcs: Sis3820McsIO, *, hinted_channels: Sequence[int] = (), poll_period: float = 1.0)`; owns `ThreadPoolExecutor(max_workers=1, thread_name_prefix="sis3820-hdf")` (every h5py call runs on this one thread: no event-loop blocking, and `close` is ordered after any in-flight write), `self._rows_written, self._set_rows_written = soft_signal_r_and_setter(int, 0)`, `_file = None`, `_task = None`.
- Constants: `_CHUNK_ROWS = 1024`; key per channel `f"{datakey_name}-channel{n}"`; dataset `f"/{key}"`; dtype `"<i4"` (raw 32-bit mca counts).
- `prepare_unbounded(datakey_name)`: `path_info = self.path_provider(datakey_name)`; `_ensure_directory(path_info)`; in the executor open `Path(path_info.directory_path) / f"{path_info.filename}.h5"` with `h5py.File(path, "w-", libver="latest")` (never clobber), create one dataset per channel (`shape=(0,)`, `maxshape=(None,)`, `dtype="<i4"`, `chunks=(_CHUNK_ROWS,)`), `swmr_mode = True`, `flush()`; `_set_rows_written(0)`; `_task = asyncio.create_task(self._write_acquisitions(keys))`; return `StreamResourceDataProvider(uri=f"{path_info.directory_uri}{path_info.filename}.h5", resources=[StreamResourceInfo(data_key=key, shape=(), chunk_shape=(_CHUNK_ROWS,), dtype_numpy="<i4", parameters={"dataset": f"/{key}"}) ...], mimetype="application/x-hdf5", collections_written_signal=self._rows_written)`.
- `_write_acquisitions(keys)`: loops over acquisitions (a `StandardDetector` reuses providers across re-prepare within one stage), `base = 0`:
  1. `async for value in observe_value(mcs.acquiring): if value: break`; `start_ts = (await mcs.acquiring.read())[mcs.acquiring.name]["timestamp"]`; `expected = await mcs.nuse_all.get_value()`.
  2. `done = 0`; loop: `running = await mcs.acquiring.get_value()` (read before the arrays: the SIS38XX SNL processes every mca record before clearing `Acquiring`, so arrays read after a False are final); `readings = await asyncio.gather(*(sig.read() for sig in mcs.mcas.values()))`; only if every reading's `timestamp >= start_ts` (arrays not processed since EraseStart still hold the previous acquisition): `n = min(len(values))`; if `n > done`, in the executor resize datasets and write rows `[done:n]` at file rows `[base+done : base+n]`, `flush()`, then `done = n`, `_set_rows_written(base + n)`. If not `running`: break; else `await mcs.read_all.trigger()` and `await asyncio.sleep(poll_period)`.
  3. If `done != expected`: raise `RuntimeError(f"SIS3820 acquisition ended with {done} of {expected} channels")` (no padding/truncation; legacy padded with `1e10`). Else `base += done`.
  - Exceptions: `logger.exception(...)` and re-raise.
- `stop()`: cancel `_task` and await it; close `_file` in the executor; reset both; then, if the task had finished with an exception other than `CancelledError`, re-raise it (the detector's `complete` can only time out on `collections_written`; this surfaces the root cause at unstage).
- `get_hinted_fields(datakey_name)` → `[f"{datakey_name}-channel{n}" for n in hinted_channels]`.
- Module function `_ensure_directory(path_info)`: `parts` = directory parts without the root; `depth = path_info.create_dir_depth`; `depth == 0` → directory must exist else `OSError(f"Directory {directory} does not exist")`; otherwise `i = depth if depth > 0 else len(parts) + depth`, root + `parts[:i]` must exist else `OSError`, then `mkdir(parents=True, exist_ok=True)` (IOC `CreateDirectory` semantics per `PathInfo.create_dir_depth`).

`class Sis3820McsDetector(StandardDetector)`, `__init__` only: `(self, prefix: str, path_provider: PathProvider, *, input_mode: Sis3820InputMode, channel_numbers: Sequence[int] = range(1, 33), count_on_start: bool = True, hinted_channels: Sequence[int] = (), poll_period: float = 1.0, name: str = "")` → `self.mcs = Sis3820McsIO(prefix, channel_numbers=channel_numbers)`; `self.add_detector_logics(Sis3820TriggerLogic(self.mcs, input_mode, count_on_start), Sis3820AcquireLogic(self.mcs), Sis3820HDFDataLogic(path_provider, self.mcs, hinted_channels=..., poll_period=...))`; `super().__init__(name=name)`.

- `program_lines(program, *, coord_sys: int, prog_num: int, trigger_var: str) -> list[str]` (pure; legacy text, `T` = trigger_var): `f"{T}=0"`, `f"open prog {prog_num};inc;linear;L1=0;"`; 2D: `f"while (L1<{lines - 1}) {{"`, `f"{T}=1;F({fast_speed:.5f});x({fast_distance:.5f});dwell 0;{T}=0;F({return_speed:.5f});x({-fast_distance:.5f})y({slow_step:.5f});L1=L1+1;dwell {line_dwell * 1000:.2f};}}"`, `f"{T}=1;F({fast_speed:.5f});x({fast_distance:.5f});dwell 0;{T}=0;"`; 1D (`slow_motor is None`): `f"dwell {line_dwell * 1000:.2f};{T}=1;F({fast_speed:.5f});x({fast_distance:.5f});dwell 0;{T}=0;"`; then `"dwell 0; close;"` and one assignment line `f"&{coord_sys};#{fast_motor}->x;"` (+ `f"#{slow_motor}->y;"` for 2D).
- `@dataclass class PpmacProgramFlyableLogic(FlyableLogic[PpmacRasterProgram, None])`, fields `gpascii: GpasciiChannel`, `coord_sys: int = 6`, `prog_num: int = 41`, `trigger_var: str = "M100"`, `clear_coord_systems: tuple[int, ...] = (5, 6, 7)`, `poll_period: float = 0.1`; every gpascii call via `asyncio.to_thread`:

  - `on_kickoff(ctx)`: send `f"&{coord_sys}begin{prog_num}r"`.
  - `on_complete(ctx)`: poll `get_variable(f"Coord[{coord_sys}].ProgActive", int)` every `poll_period` until 3 consecutive `0` (start-latency handling of `ppmac.pp_comm.GpasciiChannel.run_and_wait`); `None` reply → `RuntimeError(f"No reply from Power PMAC for Coord[{coord_sys}].ProgActive")`; then `ErrorStatus` nonzero → `RuntimeError(f"Power PMAC coordinate system {coord_sys} program {prog_num} ended with ErrorStatus={err}")`.
  - `stop()` (the interface's stage/unstage hook): send `"".join(f"&{c}abort;undefine;" for c in clear_coord_systems)` then `f"{trigger_var}=0"`. Frees the motors from any coordinate system before EPICS moves and aborts at unstage (legacy 2D cleared 5,6,7; legacy 1D 6,7; unified).

Both delegate to one private `_panda_flyscan(...)`:
  1. Validate before any Msg (`ValueError`): `num1, num2 >= 1`; `num1*num2 <= MAX_TOTAL_POINTS`; `0 <= dead_time < exposure_time`; `position_supersample >= 1`; `scan_end1 != scan_start1`; motor names in `PPMAC_MOTOR_NUMBERS` (`"Undefined motor for fly scan: <name>"`); `return_speed = abs(return_speed) <= MAX_SPEED`.
  2. `m1_pos = yield from bps.rd(motor1)` (2D also motor2); `start1 = m1_pos + scan_start1`, `range1 = scan_end1 - scan_start1`, `vx = range1/(exposure_time*num1)`, `abs(vx) <= MAX_SPEED` else `ValueError("Stage scan speed too fast...")`; `start1_scan = start1 - vx*line_overhead[0]`; `range1_scan = range1 + vx*sum(line_overhead)`; 2D `start2 = m2_pos + scan_start2`, `range2 = scan_end2 - scan_start2`, `step2 = range2/num2`; `start1_scan`, `start1_scan + range1_scan` (2D also `start2`, `start2 + range2`) inside `SCAN_POSITION_LIMITS` else `ValueError`.
  3. Start metadata: `motors`, `motor1`, (`motor2`), `shape` (`[num1, num2]`; 1D `[num1, 1]`), `fly_type="grid"`, `plan_name`; `scan` = user `md["scan"]` updated with `type` (`"2D_FLY_PANDA"`/`"1D_FLY_PANDA"`), `scan_input` (`[start1, start1+range1, num1, start2, start2+range2, num2]`; 1D first three), `sample_name` setdefault `""`, `detectors` (`[d.name for d in detectors] + [panda.name, sclr.name]`), `dwell`, `fast_axis={"motor_name", "units"}` (`bps.rd(motor.motor_egu)`), (`slow_axis`), `shape`, `position_supersample`.
  4. `exposure_timeout = exposure_time + sum(line_overhead) + line_dwell + abs(range1_scan)/return_speed + DEFAULT_TIMEOUT`; `N = num1*num2`; `point_info = TriggerInfo(trigger=DetectorTrigger.EXTERNAL_LEVEL, number_of_events=N, exposure_timeout=exposure_timeout)`; `panda_info` identical with `number_of_events=N*position_supersample`.
  5. `flyer = motion.with_device(name="ppmac_fly")`; `yield Msg("hxn_next_scan_id")` (shared IOC scan-ID counter with step scans; RE needs `hxntools.scans.setup(RE=RE)`).
  6. `finalize_wrapper(stage_wrapper(run_wrapper(inner, md), [flyer, panda, sclr, *detectors]), return_plan)`; `return_plan`: `bps.mv(motor1, m1_pos[, motor2, m2_pos])` if `pos_return` (runs after unstage, i.e. after the PPMAC coordinate systems are aborted).
  7. `inner`: `apply_standard_fly_settings(..., exposures_per_line=num1, line_delay=line_overhead[0])`; `bps.mv` to `start1_scan` (2D also `start2`); `bps.sleep(max(SETTLE_TIME_AFTER_MOVE.get(m.name, 0.0) for moved motors))`; `bps.prepare(flyer, PpmacRasterProgram(fast_motor=PPMAC_MOTOR_NUMBERS[motor1.name], fast_distance=range1_scan, fast_speed=abs(vx), return_speed=return_speed, line_dwell=line_dwell, slow_motor=<2D: PPMAC_MOTOR_NUMBERS[motor2.name]; 1D: None>, slow_step=<2D: step2; 1D: 0.0>, lines=<2D: num2; 1D: 1>), wait=True)` (drives M100 low before arming); prepare `*detectors, sclr` with `point_info` and `panda` with `panda_info` in one group and wait (external triggering arms detectors here); `bps.declare_stream(*detectors, sclr, name=POINT_STREAM, collect=True)`; `bps.declare_stream(panda, name=PANDA_STREAM, collect=True)`; then — inside `stage_wrapper(..., [shutter])` when a shutter is given, so it is open only during acquisition — `bps.kickoff_all(*detectors, sclr, panda, wait=True)`, `bps.kickoff(flyer, wait=True)`, `group = short_uid("complete")`, `bps.complete_all(flyer, panda, sclr, *detectors, group=group, wait=False)`, `done = False`, `while not done: done = yield from bps.wait(group=group, timeout=flush_period, error_on_timeout=False); yield from bps.collect(*detectors, sclr, name=POINT_STREAM); yield from bps.collect(panda, name=PANDA_STREAM)`.
  - PandA samples form their own `panda` stream (N·s events, each with its own `TS_TRIG`): a different cadence from the per-point `primary` stream; point k ↔ rows `[k*s, (k+1)*s)` via `scan.position_supersample`.
